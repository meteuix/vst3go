# 상용 플러그인 인증 및 라이선싱

이 가이드는 `vst3go` 위에서 만든 상용 플러그인에 로그인, 라이선스 키 활성화, 엔타이틀먼트(entitlement, 사용 권한) 확인을 추가하는 방법을 설명합니다.

이 문서는 제품 설계 가이드이며 법률 자문이 아닙니다. 아키텍처, 통합 지점, 운영상의 트레이드오프에 초점을 맞춥니다.

## 1. `vst3go`가 담당해야 하는 것과 담당하지 않아야 하는 것

`vst3go`가 담당해야 하는 영역:

- VST3 래퍼
- 파라미터 및 상태 연결 코드
- 에디터 스냅샷 연결 코드
- 번들/빌드/검증용 스캐폴딩

다운스트림 제품 저장소가 담당해야 하는 영역:

- 사용자 계정
- 로그인 UI
- 라이선스 키 발급
- 활성화/갱신 네트워킹
- 엔타이틀먼트 정책
- 결제 연동
- 고객 지원 절차

`vst3go`를 인증 프레임워크로 만들려고 하지 마십시오. 인증은 런타임 계층 안이 아니라 플러그인 옆에 두십시오.

## 2. 핵심 규칙: 플러그인 바이너리에만 신뢰를 두지 않기

상용 플러그인 바이너리는 최종 사용자에게 배포됩니다. 이는 다음을 의미합니다:

- 바이너리에 내장된 시크릿은 결국 추출될 수 있습니다
- 로컬에서만 수행되는 “라이선스 검사”는 패치되거나 우회될 수 있습니다
- 오프라인 토큰은 제대로 바인딩하지 않으면 복사될 수 있습니다

따라서 유일하게 신뢰할 수 있는 기준(source of truth)은 서버가 발급하거나 서명한 엔타이틀먼트 모델이어야 합니다.

플러그인은 엔타이틀먼트의 로컬 증명을 캐시할 수는 있지만, 판단의 최종 권한을 가져서는 안 됩니다.

## 3. 권장 아키텍처

가장 실용적인 상용 아키텍처는 다음과 같습니다:

1. 사용자가 계정을 만들거나 로그인합니다
2. 사용자가 라이선스 키 또는 구독 엔타이틀먼트를 활성화합니다
3. 백엔드가 서명된 엔타이틀먼트 객체를 반환합니다
4. 플러그인이 엔타이틀먼트를 로컬에 저장합니다
5. 플러그인이 백엔드와 주기적으로 엔타이틀먼트를 갱신합니다
6. 백엔드에 일시적으로 연결할 수 없으면 플러그인이 유예 기간을 허용합니다
7. 엔타이틀먼트가 만료되거나 철회되면 플러그인이 프리미엄 동작을 비활성화합니다

이 아키텍처는 다음에 모두 적용할 수 있습니다:

- 일회성 영구 라이선스
- 구독 라이선스
- 시트 기반/팀 라이선스
- 기간 제한 체험판
- 오프라인 활성화 후 추후 갱신

## 4. 엔타이틀먼트 모델을 일찍 선택하기

코드를 작성하기 전에 상용 라이선스 모델을 선택하십시오.

### 옵션 A: 라이선스 키만 사용

사용자가 키를 입력하면 백엔드가 이를 검증하고 활성화 결과를 반환합니다.

적합한 경우:

- 단순한 결제 흐름
- 영구 라이선스
- 소규모 제품 카탈로그

트레이드오프:

- 키를 공유하기가 더 쉽습니다
- 사용자가 키를 잃어버리면 지원 요청이 늘어날 수 있습니다
- 로그인도 함께 지원하지 않으면 계정 복구에 한계가 있습니다

### 옵션 B: 계정 로그인

사용자가 계정에 로그인하면 앱이 그 계정에 연결된 라이선스를 찾아냅니다.

적합한 경우:

- 구독
- 여러 제품
- 시트 관리
- 간편한 라이선스 복구

트레이드오프:

- 인증 UX를 직접 만들고 유지 관리해야 합니다
- 토큰 갱신과 세션 처리가 제품의 일부가 됩니다

### 옵션 C: 로그인 + 라이선스 키

사용자가 로그인한 뒤 키를 입력해 계정에 연결합니다.

이 모델은 다음을 지원하므로 실무에서 가장 좋은 모델인 경우가 많습니다:

- 계정 복구
- 비밀번호 재설정
- 기기 관리
- 키 등록(redemption)
- 구독 또는 영구 라이선스

대부분의 상용 오디오 플러그인에는 이 모델을 출발점으로 권장합니다.

## 5. 오디오 스레드는 관여시키지 않기

오디오 콜백은 다음을 해서는 안 됩니다:

- 네트워크 요청 수행
- UI/네트워크 코드가 보유한 락에서 블로킹
- 라이선스 서버 응답 대기
- 대용량 파일 쓰기
- 비용이 큰 암호 연산의 반복 수행

대신 다음과 같이 합니다:

- 오디오 스레드 밖에서 라이선스 상태를 검증합니다
- 결과를 메모리에 캐시합니다
- `ProcessAudio`가 가벼운 atomic 또는 lock-free 플래그를 읽도록 합니다

오디오 스레드는 다음만 확인해야 합니다:

- 이 플러그인은 현재 라이선스가 있는가?
- 유예 모드가 활성화되어 있는가?
- 프리미엄 기능이 잠금 해제되어 있는가?

이 검사는 O(1)이어야 하며 블로킹되지 않아야 합니다.

## 6. 인증 UI는 에디터 또는 별도의 설정 화면에 두기

브라우저로 렌더링되는 에디터에서는 인증 UI를 두기에 가장 쉬운 곳이 보통 에디터 셸 자체이거나 다운스트림 앱 안의 설정 패널입니다.

일반적인 화면:

- 로그인
- 라이선스 키 입력
- 이 기기 활성화
- 이 기기 비활성화
- 엔타이틀먼트 상태 보기
- 동기화 재시도
- 구매 복원

좋은 UX 원칙:

- 라이선스 UI가 설정 라우트 뒤에 숨겨져 있어도 오디오 UI는 계속 사용할 수 있도록 유지합니다
- 확실한 이유가 없다면 사용자가 별도의 앱을 방문하도록 강제하지 않습니다

## 7. 권장 데이터 흐름

흐름은 다음과 같아야 합니다:

1. 사용자가 이메일/비밀번호 또는 라이선스 키를 입력합니다
2. 다운스트림 앱이 TLS를 통해 자격 증명을 백엔드로 전송합니다
3. 백엔드가 신원과 라이선스 소유권을 검증합니다
4. 백엔드가 엔타이틀먼트 blob을 반환합니다
5. 다운스트림 앱이 엔타이틀먼트를 로컬에 저장합니다
6. 플러그인이 시작할 때 로컬 엔타이틀먼트를 읽습니다
7. 플러그인이 백그라운드에서 엔타이틀먼트를 갱신합니다

플러그인 바이너리 자체가 시크릿을 “알고 있는” 대상이어서는 안 됩니다.

## 8. 제안하는 백엔드 엔드포인트

소규모 상용 백엔드에는 보통 다음과 같은 엔드포인트가 필요합니다:

- `POST /auth/login`
- `POST /auth/logout`
- `POST /licenses/activate`
- `POST /licenses/deactivate`
- `POST /licenses/refresh`
- `GET /licenses/me`
- `POST /licenses/redeem`
- `POST /licenses/trial/start`

정확한 형태는 달라도 되지만, 이들이 일반적으로 필요한 작업입니다.

## 9. 플러그인이 로컬에 저장해야 하는 것

오프라인 시작과 빠른 재로드를 지원하는 데 필요한 것만 저장하십시오.

일반적으로 캐시하는 필드:

- 계정 ID
- 엔타이틀먼트 ID
- 제품 ID
- 라이선스 등급
- 발급 시각
- 만료 시각
- 갱신 기한
- 기기 바인딩 식별자
- 서명 또는 검증 데이터

비밀번호 원문을 저장하지 마십시오.
서버 시크릿을 저장하지 마십시오.

## 10. 서명된 엔타이틀먼트 사용하기

가장 안전하고 일반적인 패턴은 다음과 같습니다:

- 백엔드가 엔타이틀먼트 객체를 발급합니다
- 백엔드가 그 객체에 서명합니다
- 플러그인이 로컬에서 서명을 검증합니다
- 백엔드가 나중에 엔타이틀먼트를 철회하거나 갱신할 수 있습니다

이렇게 하면 플러그인이 변조 가능한 평문 플래그를 신뢰하지 않고도 로컬에서 빠르게 판단할 수 있습니다.

일반적인 엔타이틀먼트 내용:

- 주체(subject)/사용자 ID
- 제품 ID
- 라이선스 유형
- 시트 수
- 기기 ID
- 발급 타임스탬프
- 만료 타임스탬프
- 유예 기간
- 기능 플래그

서명 옵션:

- Ed25519
- ECDSA
- RSA

플러그인 제품에는 Ed25519가 잘 맞는 경우가 많습니다. 검증이 빠르고, 서버 시크릿을 만들어 내지 않고도 공개 키를 내장할 수 있기 때문입니다.

## 11. 기기 바인딩

동시 활성화 수를 제한하려면 라이선스를 기기 핑거프린트에 바인딩하십시오.

사용하기 좋은 신호:

- 머신 ID
- OS 설치 식별자
- 생성한 설치 UUID
- 계정에서 관리하는 기기 슬롯

하드웨어는 바뀔 수 있고 개인정보 보호 정책은 플랫폼마다 다르므로, 단일 하드웨어 핑거프린트에 의존하는 것은 피하십시오.

권장 방식:

- 첫 실행 시 설치 UUID를 생성합니다
- 로컬에 저장합니다
- 백엔드가 그 설치 UUID를 계정/라이선스와 연결하도록 합니다
- 사용자가 머신을 옮기면 재활성화를 허용합니다

이 방식은 보통 CPU, 디스크, 메인보드 값으로 핑거프린트를 만들려는 방식보다 덜 깨지기 쉽습니다.

## 12. 오프라인 유예 기간

상용 플러그인에는 네트워크를 사용할 수 없을 때의 합리적인 실패 처리 방식이 필요합니다.

권장 정책:

- 엔타이틀먼트 갱신에 실패하면 짧은 유예 기간을 허용합니다
- 정확한 사유를 UI에 표시합니다
- 이전 엔타이틀먼트가 유효했다면 유예 기간 동안 플러그인을 계속 사용할 수 있게 합니다
- 라이선스를 갱신할 수 없으면 결국에는 재검증을 요구합니다

이 방식은 무대 위에 있거나 비행기 안에 있거나 엄격한 방화벽 정책 뒤에 있는 사용자에게 도움이 됩니다.

## 13. `vst3go` 상태와 제품 상태에 각각 무엇을 넣을지

이 구분을 깔끔하게 유지하십시오:

- `vst3go` 상태: 플러그인 파라미터와 플러그인이 소유하는 커스텀 상태
- 제품 상태: 엔타이틀먼트 캐시, 인증 세션, 사용자 프로필, 라이선스 이력

실제로 상용 인증 상태는 VST3 상태 스트림 밖에 두는 것이 맞는 경우가 많습니다.

이유:

- 라이선스/세션 상태는 독립적인 갱신 주기가 필요할 수 있습니다
- 인증을 사용할 수 없더라도 플러그인 상태는 복원 가능해야 합니다
- 인증 정책을 바꾸더라도 사용자의 사운드 설정이 손상되어서는 안 됩니다

안전한 기본 방침은 다음과 같습니다:

- 오디오/플러그인 상태는 VST3 상태 경로에 저장합니다
- 인증 상태는 제품이 관리하는 별도 저장소에 저장합니다

## 14. 인증 상태를 저장할 위치

다음 중 하나를 선택하십시오:

- 앱 데이터 디렉터리
- 사용자 설정 디렉터리
- 암호화된 로컬 저장소
- 플랫폼 키체인 또는 자격 증명 저장소

민감한 리프레시 토큰은 가능하면 플랫폼 자격 증명 저장소를 사용하는 것이 좋습니다.

민감하지 않은 엔타이틀먼트 메타데이터는 서명되고 검증된다면 로컬 설정 파일에 두어도 됩니다.

## 15. 제안하는 저장 위치 구분

### Keychain / Credential Manager에 저장

- 리프레시 토큰
- 수명이 긴 세션 시크릿
- 정말 필요하다면 기기 시크릿

### 일반 설정에 저장

- 엔타이틀먼트 캐시
- 검증 메타데이터
- 기능 플래그
- 마지막 동기화 시각

## 16. 상용 에디터에서 `vst3go` 사용하기

플러그인이 브라우저로 렌더링되는 에디터를 사용한다면:

- 에디터에 로그인 상태를 표시합니다
- 엔타이틀먼트 상태를 명확하게 표시합니다
- 사용자가 기기를 활성화/비활성화할 수 있게 합니다
- 인증 UI를 오디오 컨트롤과 분리합니다
- 서버 응답을 기다리는 동안 에디터를 블로킹하지 않습니다

좋은 에디터 상태:

- `Signed out`
- `Signed in`
- `Activated`
- `Grace period`
- `Expired`
- `Offline, last verified on ...`

인증 패널을 사용할 수 없는 경우에도 플러그인은 로드되어 오디오 상태를 표시해야 합니다.

## 17. 권장 런타임 검사

런타임에 플러그인에 필요한 것은 단순한 엔타이틀먼트 상태 머신뿐입니다:

- `Unknown`
- `Valid`
- `Grace`
- `Expired`
- `Revoked`
- `SignInRequired`

오디오 엔진은 이 상태를 읽어 프리미엄 기능을 활성화할지 결정할 수 있습니다.

제안하는 동작:

- `Valid`: 전체 기능
- `Grace`: 전체 기능, 경고 배너
- `Expired`: 제품 정책에 따라 기능 제한 또는 음소거
- `Revoked`: 프리미엄 동작을 즉시 비활성화

강제 음소거(hard-mute) 정책은 신중하게 적용하십시오. 너무 공격적이면 고객 지원 부담이 커질 수 있습니다.

## 18. 체험판

체험판을 제공하려면 또 하나의 엔타이틀먼트 유형으로 취급하십시오.

일반적인 체험판 정책:

- 최초 활성화 시점부터 기간이 제한되는 체험판
- 설치 시점부터 기간이 제한되는 체험판
- 계정 가입이 필요한 체험판
- 유료 엔타이틀먼트로 업그레이드할 수 있는 체험판

체험판도 서명되어야 하고 갱신할 수 있어야 합니다.

로컬 시계 검사에만 의존하지 마십시오. 의미 있는 검사가 되도록 하려면 항상 서버가 발급한 기록과 함께 사용하십시오.

## 19. 오프라인 활성화

사용자가 격리된 스튜디오 머신에서 작업한다면 오프라인 활성화 경로를 제공하십시오.

일반적인 흐름:

1. 플러그인이 머신/설치 ID를 표시합니다
2. 사용자가 그 ID를 웹 포털이나 지원 양식에 복사해 넣습니다
3. 백엔드가 오프라인 활성화 파일을 생성합니다
4. 사용자가 그 파일을 플러그인/앱으로 가져옵니다
5. 플러그인이 서명을 검증하고 엔타이틀먼트를 저장합니다

스튜디오 머신이 항상 온라인 상태는 아니기 때문에 오디오 소프트웨어에서는 흔한 방식입니다.

## 20. 로깅과 개인정보 보호

인증 실패는 신중하게 로깅해야 합니다.

기록할 항목:

- 상태 코드
- 재시도 기한
- 엔타이틀먼트 상태 전이
- 서명 검증 실패

기록하지 말아야 할 항목:

- 비밀번호
- 토큰 원문
- 전체 라이선스 키
- 사용자 개인 데이터

텔레메트리가 필요하다면 옵트인 방식으로 제공하고 그 사실을 명확하게 고지하십시오.

## 21. 따라야 할 보안 규칙

- 모든 구간에서 TLS를 사용하십시오
- 서버 인증서를 검증하십시오
- 엔타이틀먼트 페이로드에 서명하십시오
- 플러그인 바이너리에 시크릿을 넣지 마십시오
- 오디오 스레드의 검사는 가볍게 유지하십시오
- 로컬 저장소는 누구든 들여다볼 수 있다고 가정하십시오
- 네트워크 요청은 실패할 수 있다고 가정하십시오
- 모든 클라이언트 측 검사는 리버스 엔지니어링될 수 있다고 가정하십시오

이것이 상용 플러그인 배포의 현실입니다.

## 22. 실용적인 `vst3go` 통합 패턴

다운스트림 저장소에서는 인증 계층이 보통 `vst3go` 내부가 아니라 플러그인 코드 옆에 위치합니다.

바람직한 분리 구조:

- `internal/auth`: 로그인, 활성화, 엔타이틀먼트 갱신
- `internal/license`: 서명 검증, 엔타이틀먼트 캐시
- `plugin`: 프로세서 및 VST3 통합
- `web`: 에디터 UI
- `cmd`: 선택적 헬퍼 앱 또는 활성화 도구

일반적인 호출 흐름:

1. 앱이 시작됩니다
2. 인증 계층이 캐시된 엔타이틀먼트를 로드합니다
3. 플러그인이 캐시된 상태로 시작됩니다
4. 인증 계층이 백그라운드에서 갱신합니다
5. 엔타이틀먼트 상태가 바뀌면 플러그인에 알림이 전달됩니다

## 23. 예시: 프로세서가 라이선스 상태를 보는 방식

프로세서는 엔타이틀먼트 상태의 가볍고 캐시된 뷰를 받아야 합니다.

예시 형태:

```go
type LicenseState struct {
	Status      string
	GraceExpiry int64
	FeatureMask uint32
}

type Processor struct {
	params       *param.Registry
	buses        *bus.Configuration
	licenseState atomic.Value
}

func (p *Processor) IsPremiumEnabled() bool {
	state, _ := p.licenseState.Load().(LicenseState)
	return state.Status == "Valid" || state.Status == "Grace"
}
```

중요한 점은 정확한 타입이 아닙니다. 중요한 점은 실시간 경로가 원격 서비스가 아니라 캐시된 상태를 읽는다는 것입니다.

## 24. 예시: 에디터에서 인증 메타데이터를 둘 위치

에디터는 다음을 표시할 수 있습니다:

- 계정 이메일
- 활성화 상태
- 기기 수
- 마지막 동기화 시각
- 만료일
- 업그레이드 링크

하지만 엔타이틀먼트의 확정 상태를 스스로 판단하는 책임을 에디터가 져서는 안 됩니다.

에디터는 그저 출입구일 뿐입니다.

## 25. 제안하는 사용자 경험

좋은 상용 플러그인 UX는 보통 다음과 같습니다:

- 플러그인이 로드됩니다
- 엔타이틀먼트가 유효하면 오디오 UI를 즉시 사용할 수 있습니다
- 사용자가 로그아웃 상태이면 인증 패널이 보이지만 셸은 그대로 로드됩니다
- 라이선스가 만료되었으면 UI가 무엇이 부족한지와 해결 방법을 설명합니다
- 오프라인이면 UI가 라이선스를 마지막으로 검증한 시점을 표시합니다

메시지는 직접적이고 차분하게 유지하십시오. 사용자는 도움말 페이지를 읽지 않고도 무슨 일이 일어나고 있는지 이해할 수 있어야 합니다.

## 26. 하지 말아야 할 것

- 인증 실패를 일반적인 오류 뒤에 숨기지 마십시오
- `pkg/plugin`에 시크릿을 넣지 마십시오
- `ProcessAudio`가 서버 응답을 기다리게 만들지 마십시오
- 로컬 시스템 시계 검사에만 의존하지 마십시오
- 디스크에 비밀번호 원문을 저장하지 마십시오
- 에디터가 오프라인이라는 이유만으로 플러그인을 사용할 수 없게 만들지 마십시오

## 27. 상용 패키징 체크리스트

`vst3go`로 만든 상용 플러그인을 출시하기 전에 다음을 확인하십시오:

- 라이선스 정책이 문서화되어 있습니다
- 오프라인 동작이 정의되어 있습니다
- 유예 기간 동작이 정의되어 있습니다
- 철회 시 동작이 정의되어 있습니다
- 접근 권한을 잃은 사용자를 위한 지원 절차가 있습니다
- 엔타이틀먼트 복구가 동작합니다
- 업데이터/인스톨러 동작이 테스트되었습니다
- host 검증이 여전히 통과합니다

## 28. 권장 시작점

처음부터 시작한다면 가장 안전한 순서는 다음과 같습니다:

1. 인증 없이 플러그인을 만듭니다
2. 백엔드와 계정 로그인을 추가합니다
3. 라이선스 활성화를 추가합니다
4. 서명된 엔타이틀먼트 캐시를 추가합니다
5. 오프라인 유예를 추가합니다
6. 기기 관리를 추가합니다
7. 철회 처리를 추가합니다
8. 체험판/업셀 UI를 추가합니다

이 순서를 따르면 시스템을 이해하기 쉽고 디버깅하기 쉬운 상태로 유지할 수 있습니다.

## 29. 최종 권장 사항

대부분의 상용 `vst3go` 제품에서는 다음 조합이 가장 균형이 좋습니다:

- 계정 로그인
- 라이선스 키 등록
- 서명된 엔타이틀먼트 캐시
- 오프라인 유예
- 백그라운드 갱신
- 제품 인증 상태와 VST3 플러그인 상태의 분리

이렇게 하면 실용적이고 지원하기 쉬우며, 순수한 클라이언트 측 라이선스 검사보다 훨씬 깨뜨리기 어려운 상용 워크플로를 갖추게 됩니다.
